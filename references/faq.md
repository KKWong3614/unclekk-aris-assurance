# 常见问题 FAQ

> 简短、带实例、有坑点对照。更多实操见 `quickstart-minimal-example.md` 与 `sample-claim-audit-report.md`。
> Short, example-driven, with pitfall comparisons.

## Q1：我是新手，不懂"异族 reviewer"怎么办？
**A：** 异族 = 用**不同模型家族**的模型当 reviewer（executor 闭源则 reviewer 用开源，反之亦然）。环境不支持就降级（详见 SKILL.md 降级路径 L1/L2/L3），并在 `results.tsv` 标注原因。降级不丢纪律——阶段顺序、P0 必改、CHECKPOINT 照旧。

## Q2：脚本能替代人工 / 异族审吗？
**A：不能。** `aris_audit.py` 只是**前置粗滤网**（默认 light 模式，纯规则、不调 LLM、不联网），会漏判也会误判。它帮你先降一轮机械缺口，最终质量闸门仍是异族对抗审查。实测证据见 `quickstart-minimal-example.md`。

## Q3：报错"找不到文件 / 不是 UTF-8"怎么办？
**A（新手友好）：**
- 找不到文件 → 检查路径拼写；优先用**绝对路径**（如 `D:/work/draft.md`）。
- 不是 UTF-8 → 在编辑器里「另存为 → 编码选 UTF-8」再跑。

## Q4：drift 漏判 / 误判了怎么办？
**A：** 脚本是启发式，对**复杂表格、代码块、中英混排**可能不准。它所有输出都标 `⚠️` 待复核——**不要盲信**，当成"待人工/异族复核的候选清单"。最终以异族审结论为准。

## Q5：对抗审查会不会死循环？
**A：不会。** 硬性上限 **3 轮**；第 3 轮 reviewer 仍打回 P0 → 收口并标注"未达成共识的争议点"，禁止无限循环。整体过程也有步数预算（见 SKILL.md「步数限制与兜底」）。

## Q6：我的结论真有证据，但 gate 还是 FAIL？
**A：** gate 只看台账三列（证据 / 强度 / 缺口）。把证据列从 `⚠️` 改成 `文件:行号`，或把缺口列写明 `已降级：…`，gate 即 PASS。例：
- ❌ 错误闭环：`| C3 | 适用所有生产 | ⚠️ | 待评 | ⚠️ |` → gate FAIL
- ✅ 正确闭环：`| C3 | 适用多数生产 | ⚠️ | 弱 | 已降级：仅小流量验证 |`

## Q7：长文（几千字）怎么用？
**A：** 同流程，但：(1) 把长文按章节拆成多段分别 `extract`；(2) 设定总步数预算（如"对抗 ≤3 轮 + 每轮 ≤5 处修订"），避免单次任务失控；(3) 全程在 `results.tsv` 留痕。

## 坑点对照表（坏做法 vs 好做法） Pitfall Cheat-sheet

| 坑 | ❌ 坏做法 | ✅ 好做法 |
|----|-----------|-----------|
| 同模型审 | executor 和 reviewer 同一模型，互相包庇 | 异族（不同家族）；不行就 L1/L2/L3 降级并登记 |
| 补不齐就发 | Ledger 留 `（应该没问题）` 直接发 | 每条 ⚠️ 三选一：补证据 / 降级措辞 / 删除 |
| 跳阶段 | 只跑阶段3 不跑 1、2 | 顺序不可跳：先证证据真，再映射，后对账 |
| 无限循环 | 轮数无上限 | 硬上限 3 轮，超时收口标争议 |
| 漏 CHECKPOINT | 审计完没留 CK 标记 | 每阶段输出 CK-0~CK-4，否则不许 Finish |
| 盲信脚本 | drift 说"无漂移"就当真 | 脚本标 ⚠️ 待复核，最终以异族审为准 |
| P0 未闭就收 | P0 打回还 Finish | gate 非零退出即阻止；P0 全闭才收口 |
